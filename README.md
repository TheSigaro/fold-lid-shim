# FoldLidShim

Костыль для Galaxy Z Fold7 (SM-F966B, Android 16) с залипшим датчиком Холла. Приложение читает угол из выбранного источника и управляет состоянием телефона. В режиме Shizuku закрытие запрашивает CLOSED (0), раскрытие по умолчанию принудительно запрашивает OPENED (3).

## Режимы работы

### Прямой режим

Использует скрытый API `DeviceStateManager` напрямую через рефлексию. Не требует adb, Shizuku или root. Процесс приложения должен быть на переднем плане.

**Шаги настройки на телефоне:**

1. Установите APK: `adb install -r out/app-debug.apk`.
2. Откройте FoldLidShim. Разрешение на уведомления не запрашивается.
3. Нажмите "Поверх других приложений" и разрешите (SYSTEM_ALERT_WINDOW) - нужно для запуска StateActivity из фоуground-службы.
4. Нажмите "Оптимизация батареи" и разрешите приложению работать без ограничений.
5. Убедитесь, что выбран режим "Прямой" в настройках.
6. Включите переключатель "Служба включена".

### Shizuku (по умолчанию)

Использует Shizuku для выполнения команд `cmd device_state` от имени uid shell. Требует adb или беспроводную отладку для запуска Shizuku.

**Шаги настройки:**

1. Установите Shizuku из Play Store (пакет `moe.shizuku.privileged.api`).
2. Запустите Shizuku через adb или беспроводную отладку.
3. В FoldLidShim переключитесь на режим "Shizuku".
4. Нажмите "Запросить разрешение Shizuku" и подтвердите.
5. Нажмите "Оптимизация батареи".
6. Включите переключатель "Служба включена".

## Логика работы

Угол <= 10 градусов без задержки (holdMs = 0) - запрос состояния CLOSED (один раз), угол >= 15 градусов - запрос OPENED (3) в Shizuku (один раз), отмена override в direct, между порогами ничего не происходит. Пороги меняются на главном экране.

## Источники угла и диагностика

В поле "Источник угла" доступны:

- `samsung`: non-wakeup Folding Angle. На SM-F966B датчик и Accelerometer-Sub требуют `com.samsung.permission.SSENSOR` (protection signature|privileged), обычному приложению и shell недоступны, поэтому по умолчанию используется `hinge`. Поиск в `getSensorList(TYPE_ALL)` сначала по строковому типу `com.samsung.sensor.folding_angle`, затем по числовому типу 65686, затем по имени с `Folding Angle`. Предполагается `values[0]` в градусах 0..180. Все исходные элементы массива показаны в блоке "Датчики", чтобы проверить формат на устройстве. Некорректные углы игнорируются.
- `accel`: основной `getDefaultSensor(TYPE_ACCELEROMETER)` и sub из `getSensorList(TYPE_ALL)` по имени, содержащему `Accelerometer-Sub` (без учёта регистра). Его строковый тип не предполагается равным `android.sensor.accelerometer`. Оба датчика обслуживает один слушатель. После получения данных обоих угол пересчитывается на каждом событии любого из них по последним векторам.
- `hinge`: прежний `TYPE_HINGE_ANGLE`, оставлен для сравнения и устройств с исправным датчиком Холла.

Все датчики регистрируются с `SENSOR_DELAY_FASTEST`; объявлено `HIGH_SAMPLING_RATE_SENSORS`. Если выбранный источник отсутствует или регистрация не удалась, это отображается в диагностике, автоматической подмены источника нет.

Для акселерометров сначала применяется инверсия выбранных осей sub: `b[i] = sub[i] * (invert[i] ? -1 : 1)`. Поле "Инверсия осей sub" сохраняет отдельные флаги X, Y, Z в Prefs, по умолчанию X=true, Y=false, Z=true. Угол раскрытия: `180 - acos(clamp(dot(main,b) / (|main| * |b|), -1, 1)) * 180 / PI`. Противоположные векторы дают 0, перпендикулярные 90, сонаправленные 180 градусов. Нулевой вектор даёт NaN и не учитывается. Результат сглаживается средним последних 5 корректных пересчётов (при прогреве используются имеющиеся отсчёты).

Залипший Холл может удерживать базовое состояние как CLOSED, так и OPENED. На этом устройстве `android.sensor.hinge_angle` постоянно выдаёт 0.0, поэтому по умолчанию он не используется. `cmd device_state state reset` возвращает к базовому состоянию и при базовом CLOSED не включает внутренний экран. Поэтому при раскрытии служба выполняет `cmd device_state state 3`. Настройка "Принудительное OPENED при раскрытии" включена по умолчанию; если выключить, раскрытие использует прежний `reset`. Служба отправляет `reset` при остановке, выключении переключателя службы и освобождении Shizuku override при смене режима, включая ранее принудительно установленное OPENED. ShizukuBridge и реализация direct не изменены. В ShellUserService к допустимым аргументам добавлен `3`, иначе существующий фильтр отвергал бы OPENED до выполнения команды. Кнопка проверки в Shizuku также раскрывает по выбранной настройке.

`StartupGate` пропускает решение только после 3 корректных событий выбранного источника. Для accel считаются только пересчёты с обоими векторами. Обратные вызовы Shizuku и таймеры счётчик не увеличивают. На третьем отсчёте FoldDecider сразу применяет текущее CLOSED или OPENED; в промежутке между порогами сохраняется гистерезис. При смене источника или инверсии сбрасываются отсчёты и сглаживание.

Блок "Датчики" обновляется каждые 200 мс, пока MainActivity открыта, даже при остановленной службе. Он показывает наличие и регистрацию источников, реальные имена и строковые типы датчиков, все сырые values Folding Angle и обоих акселерометров, время последнего события каждого датчика в секундах от загрузки, угол каждого источника, угол accel до и после сглаживания и последнее решение службы. Отсутствующее значение обозначено `-`. Диагностические подписки снимаются при закрытии экрана.

JUnit-тесты `HingeAngleMathTest` проверяют 0, 90, 180 градусов, инверсию осей и некорректные векторы. `StartupGateTest` проверяет отсутствие команд до третьего отсчёта, немедленное начальное CLOSED/OPENED, игнорирование NaN, повторный прогрев после сброса и промежуточную зону. Существующие FoldDecider-тесты сохранены.

## Тесты и сборка

JUnit 4 подключён через version catalog. Тесты в `app/src/test/` работают с чистой Kotlin-логикой без моков Android. Для Gradle нужны JDK 17 и Android SDK 36:

```bash
./gradlew --no-daemon testDebugUnitTest lintDebug assembleDebug
```

В фермерской песочнице команда запускается через подготовленную обёртку:

```bash
farm-check -C . --net -- /cache/android/with-android ./gradlew --no-daemon testDebugUnitTest lintDebug assembleDebug
farm-check -C . -- shellcheck build.sh
```

Dockerfile выполняет `testDebugUnitTest lintDebug` перед `assembleDebug`. Ошибка тестов или lint прерывает сборку. Финальная стадия `apk` копирует только APK, без отчётов lint.

Проверяемые правила `FoldDeciderTest`:

- `closesAtInclusiveThreshold` - включительный порог закрытия, отсутствие повторов до и после подтверждения.
- `opensAtInclusiveThresholdAndDoesNotRepeat` - включительный порог открытия, отсутствие повторов и лишнего стартового сброса после успеха.
- `middleZoneNeverRequestsACommand` - промежуточная зона до и после закрытия.
- `noiseYieldsExactlyOneCloseBeforeAndAfterAcknowledgement` - шум 9, 11, 9, 11 даёт одну команду.
- `closeOpenCloseProducesThreeCommands` - полный цикл из трёх команд.
- `oppositeAngleWhilePendingIsReconciledAfterResult` - противоположный угол во время ожидания direct-результата.
- `holdRequiresFullDurationAndMiddleZoneCancelsIt` - удержание 400 мс, отмена промежуточным углом, повтор после ошибки.
- `failedCloseAndOpenRetryOnNextReading` - ошибки обоих направлений разрешают повтор.
- `startupResetWaitsForSuccessSuppressesPendingDuplicatesAndRetriesFailure` - страховка старта, подавление ожидающего сброса, повтор после ошибки.
- `resetRearmsStartupSafetyAndClearsPendingCommand` - reset возвращает стартовую страховку и снимает ожидание.
- `settingsReloadPreservesActiveAndPendingCommands` - смена настроек сохраняет override, ожидающую команду и подтверждённый сброс.

`ThresholdValidationTest`: `acceptsEndpointsAndStrictlyOrderedThresholds` проверяет допустимые границы 0 и 180 и близкие пороги; `rejectsOutsideEqualAndReversedThresholds` проверяет выход за границы, равенство и обратный порядок; `rejectsNonFiniteValues` проверяет NaN и бесконечности.

В `FoldService` ветвления по порогам и флаги `holdPending`/`resetConfirmed` заменены вызовом `FoldDecider.onAngle`. Таймер удержания использует `nextEvaluationMs`; результаты Shizuku и direct (включая ошибки запуска и таймауты) передаются в `onApplied`. Активный `DirectStateController.hasRequest` подавляет только повторное закрытие, сохраняя возможность открытия. Перезагрузка порогов через `configure` сохраняет состояние; при смене режима после отмены старого override вызывается `reset`. Wake lock освобождается после события, если удержание не требуется.

### Сборка APK в Docker

Нужен только Docker, Android SDK на хосте не нужен:

```
./build.sh
```

Готовый debug APK (подпись debug) окажется в `out/app-debug.apk`. Установка: `adb install -r out/app-debug.apk`.

## После перезагрузки

Если служба была включена, она стартует сама по BOOT_COMPLETED. В прямом режиме дополнительных действий не нужно. В режиме Shizuku служба запускает свой adb-клиент по описанному ниже алгоритму. Полученный binder автоматически подхватывается существующим ShizukuBridge.

## Автозапуск без компьютера

Однократная настройка:

1. Установите Shizuku (`moe.shizuku.privileged.api`) и FoldLidShim. Разрешите FoldLidShim показывать окна поверх других приложений.
2. Один раз выдайте разрешение с компьютера:
   `adb shell pm grant dev.pavlov.foldlidshim android.permission.WRITE_SECURE_SETTINGS`.
   Разрешение сохраняется после перезагрузок.
3. Подключите телефон к Wi-Fi. На главном экране нажмите «Сопряжение adb», затем «Открыть настройки беспроводной отладки». Включите беспроводную отладку и откройте системный диалог сопряжения по коду.
4. В плавающем окне FoldLidShim введите шестизначный код и нажмите «Связать». Приложение ищет локальный порт `_adb-tls-pairing._tcp` и связывается с `127.0.0.1`. Результат виден 5 секунд, затем окно закрывается. При ошибке повторно откройте экран сопряжения и новый системный код. Окно также можно закрыть вручную; через 5 минут оно закрывается само.
5. Выберите режим Shizuku (он используется по умолчанию), включите службу, нажмите «Запустить Shizuku сейчас». Один раз подтвердите доступ FoldLidShim в Shizuku через кнопку запроса разрешения.

Wi-Fi должен быть включён и подключён к сети: Android поднимает беспроводную отладку только при подключённом Wi-Fi. Уведомления для сопряжения и управления не используются, POST_NOTIFICATIONS отсутствует. Обязательное уведомление foreground-службы остаётся на отдельном канале IMPORTANCE_MIN; его видимость можно ограничить системными настройками.

Служба при старте и при подключении Wi-Fi проверяет binder Shizuku. Если он уже доступен, никаких adb-действий нет. Без ключа или WRITE_SECURE_SETTINGS причина сразу отображается в статусе. Иначе клиент включает `adb_wifi_enabled=1`, ищет `_adb-tls-connect._tcp` через NsdManager. Если отладка уже была включена, но за 5 секунд порт не найден, переключает её 0 -> 1. Затем ждёт порт до 20 секунд, подключается по TLS 1.3 с сохранённым RSA-ключом и выполняет:

```sh
cp '<nativeLibraryDir>/libshizuku.so' /data/local/tmp/shizuku_starter && chmod 700 /data/local/tmp/shizuku_starter && /data/local/tmp/shizuku_starter --apk='<sourceDir>'
```

Оба пути берутся из PackageManager установленного Shizuku и экранируются для shell. После команды клиент ждёт binder до 10 секунд. По умолчанию после успеха выключает беспроводную отладку; переключатель «Выключать беспроводную отладку после запуска» сохраняется в настройках.

После ошибок задержки составляют 10, 20, 40, 60 секунд, затем по 60 секунд. Событие подключения Wi-Fi вызывает попытку сразу, не дожидаясь таймера. Одновременно выполняется только одна попытка. Окно автоматических попыток ограничено 30 минутами с запуска службы, ожидание сети не удерживает поток датчиков. Если Wi-Fi так и не появился, статус показывает причину и повторы, затем остановку по истечении окна. Для нового окна выключите и включите службу. Отсутствие ключа или разрешения требует настройки и ручного запуска либо нового события Wi-Fi.

В блоке «Автозапуск Shizuku» видны наличие ключа, разрешения, команда выдачи разрешения и последняя попытка: время, этап, ошибка. Подробности каждой попытки и вывод starter доступны в `adb logcat -s FoldLidShim`. Ключ создаётся только при первом сопряжении: RSA 2048, PKCS#8 в приватных SharedPreferences `adb_identity` в device-protected storage. Ключ доступен до первой разблокировки, не резервируется (`allowBackup=false`) и не заменяется при ошибке чтения. Это отдельный ключ FoldLidShim, а не ключ приложения Shizuku. Служба запускается на BOOT_COMPLETED, не на LOCKED_BOOT_COMPLETED.

Клиент и нативный SPAKE2 перенесены из [RikkaApps/Shizuku](https://github.com/RikkaApps/Shizuku/tree/b844bc491f1790c72328e1a8e5b2349f8978f0ea/manager/src/main), Apache-2.0. Подробности адаптации в NOTICE, лицензия в LICENSE-Shizuku. Зависимости Bouncy Castle, Conscrypt и BoringSSL объявлены в version catalog; для сборки JNI требуется Android NDK 28.0.13004108 и CMake 3.22.1. Тесты `RetryPolicyTest` проверяют задержки и границу 30 минут, `AdbMessageTest` - CNXN, OPEN/WRTE, checksum, magic, размеры и усечённый поток. Существующие тесты не изменены.

## Как отключить

- Выключите переключатель "Служба включена": при остановке служба снимает свой override.
- Если override завис (например, процесс убит), снимите его вручную: `adb shell cmd device_state state reset`.

## Логи

`adb logcat -s FoldLidShim` - каждое изменение состояния и каждая команда с кодом возврата и выводом.
