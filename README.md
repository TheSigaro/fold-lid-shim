# FoldLidShim

Костыль для Galaxy Z Fold7, Android 16, без root. Служба читает угол через `AngleSource` (по умолчанию `hinge`) и в режиме Shizuku сверяет желаемое состояние с базовым состоянием Холла. Доступ к Samsung Folding Angle и Accelerometer-Sub закрыт разрешением `com.samsung.permission.SSENSOR` уровня signature|privileged. Приложение, shell и Shizuku получить его не могут.

## Ключ adb с компьютера

Основной путь - один раз импортировать ключ ноутбука, который уже авторизован на этом телефоне через USB с опцией «Всегда разрешать»:

```sh
adb push ~/.android/adbkey /sdcard/Download/adbkey
```

В карточке Shizuku нажмите «Импортировать ключ adb», выберите файл `adbkey`. Поддерживается PEM `BEGIN PRIVATE KEY`, PKCS#8, RSA 2048. PKCS#1 `BEGIN RSA PRIVATE KEY`, другие размеры и мусор отклоняются с сообщением «Это не ключ adb». Файл остаётся в Download - после импорта удалите его вручную. Затем выполните:

```sh
adb shell pm grant dev.pavlov.foldlidshim android.permission.WRITE_SECURE_SETTINGS
```

Ключ и флаги `adb_key_paired=true`, `adb_key_imported=true` сохраняются одним commit через `PreferenceAdbKeyStore` в приватном device-protected хранилище `adb_identity`. Резервное копирование выключено. Статус ключа: «нет», «импортирован», «сопряжён». Старый ключ без `adb_key_paired=true` считается несопряжённым: «нет (нужен импорт)», автозапуск его не использует.

Запасной путь - «Сопряжение adb». Откройте этот экран в split-screen вместе с Настройками. В Настройках включите беспроводную отладку и откройте диалог кода. Введите шесть цифр в поле приложения и нажмите «Связать». Настройки должны оставаться resumed: уход в фон закрывает сервер `_adb-tls-pairing._tcp`. Оверлей удалён. Новый ключ готовится в памяти для протокола, в настройки попадает только после успешного сопряжения. Неудачная попытка не заменяет сохранённый ключ.

## Запуск и автозапуск Shizuku

1. Установите Shizuku (`moe.shizuku.privileged.api`) и приложение.
2. Импортируйте авторизованный ключ и выдайте WRITE_SECURE_SETTINGS по инструкции выше.
3. Подключитесь к Wi-Fi. Кнопка «Запустить Shizuku» открывает Shizuku, «Запустить автоматически» запускает существующий автозапуск v5.
4. Когда Shizuku работает, нажмите «Выдать разрешение» и подтвердите доступ приложения.
5. Включите службу. При необходимости отключите оптимизацию батареи.

Автозапуск проверяет binder. Если Shizuku доступен, пишет «Shizuku уже работает». Иначе включает `adb_wifi_enabled`, ищет локальный `_adb-tls-connect._tcp`, подключается по TLS с сохранённым ключом и запускает starter установленного Shizuku. При отсутствии порта выполняется переключение беспроводной отладки. После успеха настройка «Выключать беспроводную отладку после запуска» выключает её (включена по умолчанию).

Повторы после ошибок: 10, 20, 40, 60 секунд, далее по 60 секунд, окно 30 минут. Событие Wi-Fi вызывает попытку сразу, одновременно работает одна попытка. Без ключа или WRITE_SECURE_SETTINGS причина показывается в карточке Shizuku. Последняя попытка содержит время, этап и ошибку. Если служба включена, BOOT_COMPLETED запускает её после перезагрузки; LOCKED_BOOT_COMPLETED не используется.

## Диагноз Холла и что делает костыль

`HallDiagnosis` хранит историю только за текущую сессию службы: минимум и максимум настоящего hinge, последний угол, изменения базового состояния. Override не считается изменением Холла. Hinge наблюдается отдельно от выбранного управляющего источника.

- «работает»: базовое состояние менялось и сейчас согласуется с углом (0 в закрытой зоне, 2/3 в открытой). Совпавший override снимается.
- «залип открыто»: базовое всегда 2/3, hinge менялся. Закрытие запрашивается по углу, при раскрытии возвращается базовое открытое состояние.
- «залип закрыто»: базовое всё время 0, получен hinge 0.0 и максимальный угол сессии остался 0.0, прошло хотя бы 60 секунд. Служба не отправляет команды по углу. Используйте ручные кнопки или плитку.
- «пока неясно»: данных недостаточно или они не согласуются. Отсутствие событий hinge не приравнивается к нулевому углу.

Диагноз пересчитывается при событиях выбранного источника и при 30-секундном опросе, поэтому отсутствие новых событий нулевого hinge не мешает выдержке 60 секунд. История сохраняется до остановки службы, при восстановлении Холла диагноз может перейти в «работает» без перезапуска.

Перед автоматическим изменением состояния в Shizuku читается сырой `dumpsys device_state`, который разбирает чистый `DeviceStateInfo`. Базовое состояние отделено от `mOverrideState` и `Override Request active`. `ReconcilePolicy` выбирает команду:

| Желаемое состояние | Базовое состояние | Наш override активен | Команда |
| --- | --- | --- | --- |
| CLOSED | 0 | да | reset |
| CLOSED | 0 | нет | ничего |
| CLOSED | 1, 2, 3, 4, 5 | любое | state 0 |
| OPENED | 2, 3 | да | reset |
| OPENED | 2, 3 | нет | ничего |
| OPENED | 0, 1, 4, 5 | любое | state 3 |
| CLOSED / OPENED | чтение не удалось | любое | state 0 / state 3 по углу |

Таблица для включённого «Принудительное OPENED при раскрытии». Если настройка выключена, вместо `state 3` используется прежний `reset`. Чужой override не снимается только потому, что базовое состояние совпало: нужна локальная отметка об успешно отправленной нашей команде и активный override в dumpsys. Если override исчез или его состояние отличается от нашего запроса, локальное владение сбрасывается.

В `FoldService.reconcileTick` на рабочем Handler раз в 30 секунд перечитывается состояние. `ShizukuBridge.releaseMatchingOverride` снимает только совпавший наш override командой `reset`. Таймер не повторяет `state 0/3`. Служба, плитка и кнопки используют общий сериализованный ShizukuBridge и общий учёт желаемого состояния, поэтому ручной запрос также участвует в сверке. Системное текущее состояние для плитки читается через `cmd device_state print-state`.

Угол <= 10 градусов по умолчанию закрывает без выдержки, >= 15 раскрывает, между порогами действует гистерезис. Пороги валидируются: `0 <= закрыто < открыто <= 180`, конечные значения. `StartupGate` по-прежнему ждёт три корректных события управляющего источника; `FoldDecider` подавляет повторы, обрабатывает удержание, ошибки и смену направления. Смена источника сбрасывает прогрев, но не историю Холла.

## Плитка

Добавьте «Экран Fold» через редактирование быстрых настроек. Тап отправляет через Shizuku `state 3`, если текущее состояние 0, иначе `state 0`. Подпись показывает текущее состояние, при неготовом Shizuku плитка недоступна. Плитка работает и без запущенной службы. При STUCK_CLOSED автоматические команды службы отключены, поэтому ручное раскрытие не отменяется нулевым углом.

Те же команды доступны кнопками «Открыть принудительно» и «Закрыть принудительно» в карточке «Ручное управление». «Проверить сейчас» сохранилась: закрытие и через три секунды раскрытие по настройке. Это явная ручная проверка.

## Главный экран

Тема `Theme.Material3.DayNight.NoActionBar` поддерживает светлый и тёмный режимы. Карточки с закруглением и отступами 16 dp расположены так:

1. Статус: крупное состояние телефона, угол, диагноз Холла, действие костыля, переключатель службы справа.
2. Shizuku: статус, разрешение только при необходимости, открытие Shizuku, импорт ключа, автозапуск и запасное сопряжение.
3. Ручное управление: принудительные состояния, подсказка о плитке, проверка.
4. Настройки: shizuku/direct с предупреждением, источник, пороги, принудительное OPENED, отключение беспроводной отладки.
5. Датчики: свёрнута по умолчанию, раскрывается по тапу, сырые значения и инверсия осей sub.
6. Шторка уведомлений: пояснение и переход в настройки уведомлений Shizuku.

Источники `samsung`, `accel`, `hinge` и direct сохранены. В direct используется прежний `DirectStateController` и `StateActivity`, нужно разрешение поверх других приложений и подтверждение на экране. Недоступный выбранный источник не заменяется автоматически. Для accel сохранены инверсия осей и среднее последних пяти пересчётов. Диагностические датчики работают только пока открыт экран, обновление 200 мс.

## Как убрать уведомления из шторки

Приложение не объявляет и не запрашивает POST_NOTIFICATIONS. Обязательное foreground-уведомление создаётся до работы службы на канале IMPORTANCE_MIN, с `setSilent(true)`, без `FOREGROUND_SERVICE_IMMEDIATE`. Отозванное разрешение не является условием запуска службы: `startForeground` вызывается независимо от него. Android требует small icon для foreground-уведомления; убрать её полностью через публичный API нельзя, видимость ограничивается каналом и системным разрешением. Android может показывать службу в системном списке активных приложений.

Уведомление «Shizuku работает» принадлежит другому пакету. Кнопка «Скрыть уведомление Shizuku» открывает `Settings.ACTION_APP_NOTIFICATION_SETTINGS` с `EXTRA_APP_PACKAGE=moe.shizuku.privileged.api`. Отключите уведомления там вручную.

## Проверки и сборка

```sh
farm-check -C . --net -- /cache/android/with-android ./gradlew --no-daemon testDebugUnitTest lintDebug assembleDebug
farm-check -C . -- shellcheck build.sh
```

JUnit: `DeviceStateInfoTest`, `ReconcilePolicyTest`, `HallDiagnosisTest`, `AdbKeyPemTest`, а также существующие тесты FoldDecider, StartupGate, порогов, углов, adb-протокола и повторов. Нужны Android SDK 36, JDK 17, NDK 28.0.13004108, CMake 3.22.1. Docker-образ содержит NDK и CMake. `./build.sh` собирает через Docker APK в `out/app-debug.apk`.
